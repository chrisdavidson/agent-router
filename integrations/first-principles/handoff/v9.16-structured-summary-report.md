# v9.16.0 Structured Summary — final report for agent-router

Every `first-principles` analysis report now ends with exactly one fenced JSON block that
restates decisions the report's own prose already contains. It adds no reasoning of its own —
the prose stays the deliverable, and a reader who ignores the block loses nothing. The block
exists so agent-router's `trace.py` can read those decisions directly from structured data
instead of pattern-matching free prose. Reading the block is `trace.py`'s own job (TRACE-01),
owned by agent-router and out of scope for this release — this report hands over the schema,
the block's placement, the live 14-run evidence, and every disagreement found between the block
and the prose it restates, so that work can start from a measured baseline rather than the
handoff spec's original six hand-found parser failures.

**Source reading:** `docs/structured-summary-live-reading.md`
**Source data:** `tests/structured-summary-live/result.json`

## Schema

Shipped file: `first-principles/references/summary-schema.json` (emitted verbatim from source
`shared/spine/references/summary-schema.json` — edit the source, never the emitted copy).

**Evolution rule**, quoted from the schema's own `versioning` field: "`schema_version` is an
integer starting at 1. Changes are add-only: adding a field keeps the version; removing or
renaming a field, or narrowing an enum, increments it."

### Top-level fields (all ten are `required`)

| Path | JSON type | Nullable | Null exactly when |
|---|---|---|---|
| `schema_version` | integer (`const: 1`) | No | — |
| `run_mode` | string | Yes | The document records no Step 0 mode (a legacy worked example). An agent report never writes null. |
| `assumptions` | array | No | — |
| `ground_truths` | array | No | — |
| `chains` | array | No | — |
| `dead_ends` | array of string | No | — (empty array when section 5 holds only its "Nothing material here" line) |
| `techniques` | object | Yes | The document has no `Techniques not applied:` block (a legacy worked example). An agent report never writes null. |
| `gate` | object | Yes | The document carries no `## Self-Audit Gate (process output)` section (a legacy worked example). A report whose gate did not run writes `passes` as `[]` and `cleared` as `false`, never null. |
| `re_entry` | object | Yes | The document records no Self-Audit Gate section and no re-entry disclosure (a legacy worked example). An agent report never writes null. |
| `conclusion` | object | No | — |

`run_mode`'s value is `full-composer` or `focused-<technique>`, where `<technique>` is one of
`five-whys`, `fishbone`, `inversion`, `pre-mortem`, `trade-off`, `second-order`, `estimate`,
`theoretical-limit` — so the full admitted value set is `full-composer`, `focused-five-whys`,
`focused-fishbone`, `focused-inversion`, `focused-pre-mortem`, `focused-trade-off`,
`focused-second-order`, `focused-estimate`, `focused-theoretical-limit`.

| Field | JSON type | Source |
|---|---|---|

| Field | JSON type | Enum values / source |
|---|---|---|
| `recommendation` | string | Section 6's `**Recommended approach:**` text, in full and verbatim, including every item of any list it introduces. Never cut at a colon, never paraphrased |
| `confidence` | string | `HIGH`, `MEDIUM`, `LOW` |

## Where the block is written

The block is the **last element** of the delivered `.first-principles/analysis-<UTC>.md` file's
`## Appendix — process output` section — the exact heading `shared/spine/references/output-template.md`
(emitted to `first-principles/references/output-template.md`) prescribes: "one `## Appendix —
process output` heading; then every process-output block produced during the [run]." Inside
that section, the structured summary is its own trailing block: the heading `## Structured
summary (process output)`, then exactly one fenced `json` block, and nothing after it
(`shared/spine/SKILL-body.md`: "The structured summary closes the appendix.").

**The agent's final message does not carry the block.** It is a short pointer only — the file's
path, a repeated disclosure if any, a statement that the file is the complete analysis, and the
Conclusion's recommendation and confidence in one or two sentences — and `SKILL-body.md` is
explicit that neither the file-handoff final message nor the fallback final message (used when
the file cannot be written) carries the structured summary: "It belongs to the file alone: the
final message does not carry it, and neither does the final message written when the file
handoff fails." (D-08.) This is a deliberate correction, not an oversight: a long block folded
into the final message would reopen the output-limit loss v9.13.0's answer-first delivery fix
cured — the same reason the six-section analysis itself moved out of the final message and into
the delivered file.

**The block is process output about the analysis, never environment state.** The output
template's own rule — "Nothing about the environment enters the document" — applies to the
block unchanged: tooling, connector, authorisation, permission, quota, configuration, model,
harness and transcript state have no place in it, exactly as they have no place anywhere else in
the delivered file (D-04).

**Checker:** `scripts/check-summary-block.py <report>` — the default **live** mode (no
`--exemplar` flag) validates a live analysis report, including its cross-checks against the
report's own prose; the `--exemplar` flag switches to exemplar mode for validating
`shared/examples/*.md` worked examples, which carry looser nullability rules (D-15). Other flags
the script's own `--help` prints: `--json` (machine-readable output), `--schema SCHEMA`
(override the schema path), `--self-test`, `--describe`.

## Block-vs-prose disagreements

**None.** The checker failed 5 of the 14 reports (`personal-general`, `personal-general-2`,
`self-application`, `software-systems-2` on `SB-TECHNIQUES`; `science-engineering` on
`SB-CHAIN-RESTS-ON` and `SB-REENTRY`), but READING confirms, for every one, that the block's own
field value matches its own report's prose once the finding's actual cause is read through — the
block was never the thing wrong:

- The four `SB-TECHNIQUES` failures are a **template** gap: `shared/spine/SKILL-body.md:125`
  prescribes the bare form `<technique> — not applicable — <reason>` with no syntax for naming
  which mode of a two-mode technique (five-whys' causal vs. reduce-to-primitives modes) or which
  phase of a two-phase technique (`theoretical-limit`, `inversion`, each invoked at two phases)
  is meant. In all five offending lines the block's `not_applied` entry is correct — checked
  directly against each report's own JSON — and the agent's prose simply wrote a disambiguating
  qualifier (`(causal mode)`, `(Phase 1 reframe)`) the checker's `_TECH_NOT_APPLIED_LINE_RE`
  cannot parse. None of the 14 `shared/examples/*.md` worked examples carry a `Techniques not
  applied:` block at all, so this was not taught by anything the agent read.
- The two `science-engineering` failures are **checker** bugs, not analysis errors: `_chain_head_refs`
  (`scripts/check-quality-harness.py:5681`) returns the first GT-mentioning line it scans rather
  than the true arrow-led chain head three lines later, so it mistakes a scene-setting sentence
  for the chain's head; `_ANY_EDGE_NAME_RE` (`scripts/check-summary-block.py:1055`) is a plain
  substring search with no negation handling, so it matches the literal phrase "re-entry edge"
  inside the report's own negated sentence "No re-entry edge fired." Both are confirmed directly
  against the report's prose and the block's `chains`/`re_entry` fields, which already agree with
  each other.

No finding in this run traces to the block itself carrying a wrong value, and none traces to a
worked example teaching a wrong form. The checker was not edited to pass any of these (D-07); both
defects are recorded as findings for a future phase, not fixed here.

**What the checker's cross-checks do not reach**, read from `scripts/check-summary-block.py
--describe`'s own `disclosed_bounds_anchors` (7 entries, not from memory): `rests_on` order is
never compared, only set membership (`rests_on-order-not-compared`); a `not_applied[].phase`
disagreement is only checked where the prose line states a phase at all
(`not-applied-phase-only-where-stated`); `techniques.applied` is schema-validated only — the
prose carries no fixed marker for an applied technique, so nothing cross-checks it against prose
(`techniques-applied-vocabulary-only`); `run_mode` is compared only when the document states a
labeled `MODE = ...` line outside the block (`run-mode-only-where-stated`); bold markers (`**`)
are stripped before comparing `conclusion.recommendation`, so a recommendation that differs only
in bold-emphasis placement is not flagged (`recommendation-bold-markers-ignored`); `re_entry` is
read only from the Self-Audit Gate's fixed span and the disclosure region, never from anywhere
else in the document (`reentry-read-from-gate-span-and-disclosure-only`); and the second-order
pass's re-challenge edge and the mid-run input re-open edge are each recognized only via a
disclosed paragraph, not inferred from prose elsewhere
(`second-order-and-input-reopen-edges-need-a-disclosed-paragraph`). "None" above means none of
these 14 runs produced a genuine disagreement the checker's cross-checks *can* see — not that no
disagreement is possible outside what the checker reaches.

## Block vs. agent-router's `trace.py` parser

Separate from the above: `tests/structured-summary-live/crossread.json` records 39 disagreements
between the block and agent-router's own `trace.py` prose parser across these same 14 runs. Every
one was read against `trace.py`'s source and found to be a parser coverage gap or a disclosed,
deliberate divergence — never a case of the block being wrong: `run_mode` (13/14, parser never
extracts a label the prose doesn't write), `re_entry.fired` (8/14, parser requires the literal
word "re-entry," absent when nothing fired or when the prose says "Fix/Repeat loop fired" instead),
`gate.passes` (7/14, parser cannot read this repo's one-line `**Pass N (before re-score):**`
summary form for an earlier pass), `gate.cleared` labeled `parser_rule` (2/14, `trace.py`'s
stricter no-`Hand-wavy`-at-all rule vs. this rubric's one-`Hand-wavy`-cap rule — a disclosed
divergence, protocol §4(c), neither side wrong), and `conclusion.recommendation` (9/14, a plain
400-character truncation in `trace.py`'s own `_trunc`, the block carrying the recommendation in
full in every case). All six of the original handoff spec's parser failures are resolved as read
from the block in this run; the two that persist in `trace.py` itself (`gate.passes`
undercounting, the 400-character recommendation cut) are TRACE-01's problem on agent-router's
side, not this repository's. Full field-by-field detail is in READING's own "Block vs parser"
section.
